# Phantom 双端省电与网络层空闲治理：事件驱动界面、可编辑白名单与四维性能观测

## 摘要

面向 Android 与 HarmonyOS 两端做一次「**界面与行为零变化、耗电与资源占用显著下降**」的深度优化，并补齐分流规则的自定义能力与 CPU / 内存 / 网络 / 耗电四个维度的量化观测手段。隧道协议、服务端、分流语义、`phantom://` URI 格式、`themeMode` 语义全部不变。

四条主线并行、互不阻塞：

| 主线 | 内容 | 收益 |
|---|---|---|
| 一 | 界面彻底事件驱动（两端），不再自己轮询 | 退后台后界面层零周期唤醒 |
| 二 | 网络层空闲治理（公共数据面） | 本次收益大头：安静流不再永驻 |
| 三 | 设置面板可编辑白名单（两端功能拉齐） | 用户可自定义分流 |
| 四 | 四维可观测性（adb / hdc 脚本化采集） | 后续改动可量化验证 |

## 关键改动

### 主线一：界面事件驱动

**Android**

- `TunnelController.kt` 明确为**进程内唯一状态源**；`PhantomVpnService`（已在跑的前台服务）作为唯一发布者：**状态跃迁点即时发布一次** + 运行期 1s 发布；重连结束后计数归零。
- `PhantomTunnelViewModel.kt` 删除 200ms 状态轮询与 `init` 无条件启动；日志 / 统计采集改为可启停，由界面可见性驱动。
- `MainActivity.kt` 用 `repeatOnLifecycle(Lifecycle.State.STARTED)` 门控采集，界面改 `collectAsStateWithLifecycle()` 订阅 `StateFlow`。
- `MainActivity.kt` 的 `SideEffect` 加 `remember` key，避免每次重组写 4 个 window 属性。
- `PhantomVpnService.kt` 看门狗把 `delay(1_000)` 移到 `if (!desiredRunning) continue` **之后**。
- `ui/LogPanel.kt` 的 `LazyColumn items` 补 `key`。
- `ui/ServerScreen.kt` 轮询加门控（仅运行或启动中）。

**HarmonyOS**

- `PhantomVpnExtensionAbility.ets` 的 `publishStatus` 改为**变更去重**（保留首次必写），对齐同文件 `publishStats` 已有范式；`STATUS_FILE` 不再每秒 TRUNC 重写。
- `VpnBridge.ets` 的 `readStatus` / `readStats` 按 `statSync` 变更检测（复用 `readLogTail` 的范式）。
- `Index.ets` 刷新启停改由 `onPageShow` / `onPageHide` 驱动，`aboutToDisappear` 兜底保留。
- `ServerPage.ets` 加「非空闲才轮询」门控。

**硬要求**：跃迁点必须显式发布一次状态，否则会出现「点了启动但按钮还是旧状态」。

### 主线二：网络层空闲治理

公共数据面，是本次收益最大的部分。

1. `TcpFlowState` 新增 `last_activity_at`，**只按真实收发续期**（纯 ACK 往返不算）；空闲超时 120–300s 后主动发 RST 并 `flows.remove`，relay 任务随之结束。当前安静流走 `unacked == 0` 分支只清 `stalled` 后 `continue`，**永不被回收**，且每流常驻一个 500ms 唤醒的重传监督任务。
2. `FlowTable` 增加 `MAX_FLOWS` 上限与超限背压（新流直接 RST 或短队列），对齐实测过的 1.9 万 socket 峰值。
3. 直连 UDP 流加空闲超时（30–60s），回收 socket + map 条目 + 任务；代理 UDP 流加客户端侧空闲超时。
4. `tcp_pool.rs` 加低频后台清扫（约 30s 一次 `prune`）；按「应用是否在前台」与「距上次 flow 时长」把目标空闲连接数从 2 收缩到 **1（不为 0）**；回前台由 `prewarm_tcp_pool` 预热。
5. 隧道内 DNS 共享流（`ensure_dns_tunnel`）空闲 60s 无查询则断开，下次查询重建。
6. 移动端 QUIC keepalive 在空闲期显著拉长或关闭。
7. TCP OS keepalive 放宽（15s/5s/3 → 更长），死链发现由 `notifyNetworkChange` 兜底。
8. SOCKS5 入口与 UDP associate 加空闲读超时与最大连接数。
9. `DnsCache` 加容量上限 + LRU + 触达续期 + 保守 TTL（不短于应答自身 TTL、不少于 30 分钟），**必须带白名单分流回归测试**；若四条约束无法同时满足，此项降级为可选。

### 主线三：可编辑白名单

规则引擎**已支持** `DomainFull` / `DomainSuffix`（等价 `*.domain`）/ `DomainKeyword` / `DomainRegex` / `IpCidr` / `GeoIp` / `Port` / `Final` 八种规则，装配于 `rules.rs`，决策单一入口是 `whitelist::decide`。本主线不扩展规则引擎。

- 白名单**走 `ClientConfig.rules.rules`，不塞进 `phantom://` URI**，URI 保持原样。
- **IP 起止段与端口范围在界面层折算成最小 CIDR / 多条端口规则**，不改变匹配语义。
- 输入归一化移植 `client/mac/Sources/PhantomMacKit/Whitelist.swift` 的规则，保证与桌面端一致。
- Android：新增 JNI `setUserRules`（仿 `setTracePath`）在启动前注入；**并补 `whitelist::rebuild`**（当前 `start_with_config` 未调用，二次启动会复用旧 Router，属必修 bug）。
- 鸿蒙：新增**独立规则文件**跨进程传递（不扩 `mode\nuri\ntrace` 三行格式），扩展进程读取后在本进程注入。
- 设置面板标注「改动在下次连接时生效」；两端面板功能拉齐（鸿蒙补「清空历史」）。
- 新增 `RuleFormat.kt` / `RuleFormat.ets`（两端同一套归一化与校验）与 JVM 单测。

### 主线四：四维可观测性

统一三套场景（A 未连接息屏 30min / B 已连接息屏无流量 30min / C 前台亮屏 10min），脚本化采集、结构化输出。

- `scripts/measure-android.sh`：`top -H`、`dumpsys meminfo`、`dumpsys netstats`、`dumpsys batterystats`、`gfxinfo`、可选 `perfetto`。
- `scripts/measure-harmony.sh`：先探测 `hidumper` / `hiperf` / `hitrace` 可用性再采集，双 PID（界面进程与扩展进程分别采）三场景，输出同构 JSON。
- 统一 JSON 字段：`cpu` / `mem` / `net` / `power` / `wakeups` / `idle_objects` / `probe`。
- `client/harmony/docs/PERF_TOOLS_GUIDE.md` 目录列了 20 节而正文只有 1–7 节，需补全或修正目录，并标注本轮实际可用项。

## 接口与契约变更

- 新 JNI：`setUserRules(json: String): Int`（Android，务必带 `@JvmStatic`）。
- 新 NAPI：鸿蒙 `phantomHarmonySetRules(json)`。
- 新偏好键：`userRules`（两端同名同义）。
- 新增文件：`RuleFormat.kt`/`RuleFormatTest.kt`、`WhitelistEditor.kt`、`RuleFormat.ets`、`scripts/measure-*.sh`。
- 隧道/服务端协议、分流语义、`phantom://` URI、`themeMode`、用户可见行为常量（`RECONNECT_DELAYS_MS`、`NET_CHANGE_BANNER_MS` 等）**全部不变**。

## 测试与验收

- 自动化：`cargo check --workspace --all-targets`、`cargo test -p phantom-client --lib`、`./gradlew :app:test`（含新增 `RuleFormatTest`）。
- 分流回归：缓存受压、规则增删后，被墙站点仍判定走隧道、直连站点仍直连；长连接（即时通讯 / 服务端推送 / 流式响应）不被空闲回收误杀。
- 安卓真机：三场景 CPU/内存/网络/耗电四维采集，场景 A 周期唤醒为 0，场景 B 唤醒数相对基线下降 ≥ 80%；状态跃迁即时（无「点过启动按钮还是旧状态」）。
- 鸿蒙真机：先探测工具可用性再采集，降级路径可用；`hitrace` 验证状态写盘去重后磁盘写事件显著减少。
- 模拟器仅用于同环境改动前后 A/B；耗电结论以真机为准。

## 假设与默认

- 空闲回收阈值取足够长（TCP 120–300s、UDP 30–60s），宁可少回收也不误杀长连接。
- 白名单「下次连接生效」，不实现移动端热重载（移动端无 `config_path`，且热重载不含 whitelist）。
- 不引入唤醒锁；鸿蒙不申请长时任务。
- 鸿蒙新增 API 逐个核对 `.d.ts` 的 `@since` 不超过 20。
- 观测脚本先探测工具再采集，探测失败降级而不中止。
- 新增或修改目录内容时同步对应 `README.md`（根 `AGENTS.md` 硬约定）。
