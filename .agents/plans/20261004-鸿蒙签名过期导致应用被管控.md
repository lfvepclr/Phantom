# 鸿蒙 7.x 应用无法启动：签名过期 + AppGallery 管控修复方案

- 计划日期：2026-10-04
- 真机：HOP-AL00，HarmonyOS 7.0.0.109，API 26（设备 UDID 与 app id 已脱敏，不入库）
- 涉及模块：`client/harmony/`、`scripts/`

## 1. 结论（先测后修）

应用无法启动**不是代码崩溃、不是 TUN/NAPI 初始化失败、不是 6.x/7.x SDK 不兼容**。
直接证据：

```text
$ hdc shell aa start -a EntryAbility -b co.phantom.harmony
error: failed to start ability.
Error Code:10106105  Error Message:The target application is under control.
Error cause: The application is suspected of malicious behavior and is
              restricted from launching by the appStore
```

手机弹出 AppGallery 的 `App unavailable — This app is no longer available and
can't be used. Uninstall?`；`hilog` 出现
`control rule caller:com.huawei.hmsapp.appgallery` 与 `DisposeAlertAbility`。

根因 = **DevEco 自动签名材料只有约 14 天有效期**：

| 证据 | 值 |
|---|---|
| Profile | `~/.ohos/config/default_harmony_*.p7b`，`type=debug` |
| 有效期 | 2026-09-12 16:26 → **2026-09-26 16:26（已过期）** |
| HAP 内嵌证书 | `hap-sign-tool.jar verify-app` 离线核对叶子证书有效期同上，华为 CA 签发 |
| 设备绑定 | Profile 内 UDID 与 `bm get -u` **完全一致**（排除设备未登记） |
| 安装时间 | 2026-09-12（安装时有效，之后才过期） |
| 系统版本 | HarmonyOS 7.0.0.109；7.x 的 AppGallery 管控会主动拦截失效应用 |

## 2. 兼容性判断

`compatibleSdkVersion = 6.0.0(20)`、`targetSdkVersion = 6.1.1(24)`、实际
`compileSdkVersion = 26.0.0.105`。7.0 真机能安装并走到 BMS 启动门禁，说明
二进制与 API 兼容正常；保持 `compatibleSdkVersion` 不变即可继续支持 6.x。
本轮不改 SDK 版本、不改 `targetSdkVersion`。

## 3. 签名有效期上限

| 方案 | 证书 | Profile | 定位 |
|---|---|---|---|
| DevEco 自动签名 | 约 14 天 | 约 14 天 | 临时调试，当前事故来源 |
| AGC 调试证书 | 1 年（需实名；未实名 14 天） | 随证书，绑定 UDID | 真机调试 |
| AGC 发布证书 | 3 年（官方当前上限） | 随证书，无设备白名单 | AppGallery 分发；不授权本地 hdc 安装 |

结论：自己用、走 hdc 安装的上限是**调试证书 1 年（实名后）**。发布证书 3 年
只能随 AppGallery 上架/内测使用；本地安装会被发布 Profile 策略拒绝。

## 4. 修复方案

**A. 立即恢复（人工，需华为开发者账号）**

1. DevEco 重新勾选 `File → Project Structure → Signing Configs →
   Automatically generate signature`，刷新调试证书/Profile。
2. `scripts/check-harmony-signing.sh` 确认 `status: OK` 且 UDID 匹配。
3. `hvigorw assembleHap` 重新打包，`hdc install -r` 覆盖安装。
4. 若仍被管控：备份 URI → `hdc uninstall` → 全新安装；必要时在 AppGallery
   解除管控 / 退出纯净模式。

**B. 长期（3 年上限）**

1. AGC 申请发布证书 + 发布 Profile，配置 release signingConfig。
2. 每次发版递增 `versionCode`，通过 AppGallery 上架/内测分发。
3. CI 增加签名预检，剩余天数不足即失败。

**C. 防复发（本仓库已落地）**

- 新增 `scripts/check-harmony-signing.sh`：解析 p7b，报告类型/有效期/剩余天数/
  UDID 匹配，过期退出 1，支持 `--json`。
- `scripts/build-harmony.sh` 构建后自动预检，过期打印醒目 WARNING。
- 新增本文与 `client/harmony/docs/SIGNING_AND_STARTUP_TROUBLESHOOTING.md`，
  明确 6.x/7.x 行为差异、最长签名方案与恢复步骤。
- `scripts/sign-harmony-hap.sh` 标注为 OpenHarmony/模拟器专用，避免真机误用。

## 5. 测试与验收

- `scripts/check-harmony-signing.sh` 在过期材料上返回 1 并打印过期天数；
  在 `signingConfigs: []` 的干净 checkout 上返回 0。
- 重签后：`check-harmony-signing.sh` 返回 0、UDID 匹配。
- `hdc install -r` 成功，`aa start` 不再返回 10106105，`pidof` 有进程。
- 真机复测：首页可进、VPN 可启动、切换 Wi-Fi/蜂窝不崩、无 AppGallery 弹窗。
- 6.x 回归：使用同一份 `compatibleSdkVersion=6.0.0(20)` 产物安装启动。

## 6. 假设与默认

- 华为开发者账号可用，且 DevEco 自动签名能把当前手机 UDID 写入新 Profile。
- 手机已开启开发者模式/USB 调试（`hdc` 当前可用）。
- 设备上已安装的应用数据可丢；不可丢时先导出 URI 再卸载。
- 本轮不改 `compatibleSdkVersion` / `targetSdkVersion`，不接入 APMS。

## 7. APMS 说明

APMS 是应用性能/稳定性监控（启动、崩溃、ANR、卡顿、网络），不参与签名与
应用市场管控，不是本次启动失败的原因，也不能修复 `10106105`；待应用恢复并
上架后可选择性接入。
